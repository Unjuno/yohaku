## 今回の具体的な修正

- 主ボタンは常に開始メッセージをコピーする。端末の共有可否で動作を変えない。
- コピー後は「AIのチャットへ貼り付けて送信」が見える。自動送信・自動ログインはしない。
- 共有ボタンはサイトURLだけを共有する。取消は失敗通知や意図しないコピーへ変換しない。
- 「今日は変なのがいい」「笑いたい」「怖くないSF」など、明示した少数の表現を選択用タグへ対応させる。任意の日本語を理解する検索器と宣伝しない。
- 気分未指定の少数推薦は異なる体験の編集上の入口を使う。人気順・ユーザー評価順ではない。全件一覧の順序は維持する。
- 「周りを見る」「今の状況は？」「中断」を一度だけ案内。必要な世界の前提は描写へ織り込む。
- ガイドを通常プレイで読み上げない。ただし技術質問・取得失敗・能力の限界には事実どおり答える。
- フォームは公開内容への同意を明示し、抜粋・タグ・自己採点を必須にしない。
- DB、常時分析SDK、会話の自動保存、Issueの自動採用を追加しない。

## 反映手順

完全なチェックアウトにパッチを適用する。別途提供する適用スクリプトは、基準SHA・作業ツリーの変更有無を確認し、確認用ブランチで止まる。push、マージ、デプロイは行わない。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run test:types
npm run check:sync
npm run verify
```

`npm test` は既存契約検査に今回の回帰を加えている。`test:types` は全画面の型検査ではない。`verify` はビルド済みWorkerの検査であり、人間の音声体験ではない。

本番反映前に元のソース/公開版の識別情報を控える。レビューを通してマージし、Sitesでその版を公開する。GitHubの更新だけでSitesも更新されたとみなさない。

```sh
node scripts/check-public-beta.mjs --url https://yohaku-trpg.unjuno.chatgpt.site
```

このGET専用検査は、公開一覧・全本文・共通ガイド・代表検索・入口リンクが手元の版と一致するか検査する。失敗や取得不能をPASSにしない。公開版が別のホストを使う場合は `SITE_CONFIG.siteUrl` もその配信先へ合わせる。

続けてスマートフォンとデスクトップの実ブラウザで、コピー許可/拒否、貼り付け、共有取消、戻る操作、文字拡大、キーボード操作を確認する。対応WebMCPブラウザでは実登録・実呼出も確認し、未対応ブラウザではHTTP/コピー経路が利用できればよい。

## 初見試遊と一回の修正サイクル

**H（仮説）**: 初見の人が、制作側の口頭補助なしで「開始→一つの行動→状況確認→中断」まで進める。これは未検証の仮説。

**T（最小検証）**: 同意を得た少なくとも5人を目安に、音声とテキストを両方含めて確認する。人数は制作判断用の目安で統計的保証ではない。1人最大15分程度、嫌になれば即中断。作品・クライアント・分かる範囲のモデル/実施日を控える。全文の収集は不要。A/Bをするなら開始案内だけなど一度に一箇所だけ変え、版と割当順を記録する。

**D（判断）**: サイトの開始・コピー・取得・中断を妨げる重大な問題が出たら、その導線はFAIL。参加数不足や機能未対応で確認できない項目はUNCERTAIN。問題なしの回が出ても、全作品・全LLMでの安全や面白さを証明したとは扱わない。重大な問題を直した後は、同じ確認項目を再実行する。

**C（対立仮説）**: 案内文そのものが没入を邪魔する、コピー後の移動で離脱する、推薦に納得しない、発話割込みで情報が失われる、操作を覚えられない、専門役の知識を利用者へ要求する。

**U（不確かさ）**: 利用者の慣れ・モデル/アプリ差・音声認識・実施順・観察者の介入が影響する。少人数の便宜抽出を一般利用者全体の継続率へ外挿しない。合成標準不確かさや包含係数を推定できる測定設計ではないため数値を付けない。

面白さは「また遊びたいか」とその理由、継続は任意の自己申告で記録する。10分に届かなくても、短い体験として満足して終えた場合と、困って離脱した場合を区別する。利用者に好意的な回答や共有を要求しない。

## 変更しない決定・残件

正式ライセンスは未決定のまま。ユーザーが所有しない第三者コードを再許諾せず、CC0/0BSD等をこの作業で勝手に適用しない。「利用歓迎」と法的な再利用許諾を混同しない。コミュニティ投稿の転載・改変範囲を広げる際は、既存投稿者の許諾も確認する。

投稿本文はデータとして読み、そこに書かれたツール実行・外部送信・GMガイド変更の指示を実行しない。採用候補を人間がレビューして差分を作り、確認後に反映する。

編集（世界と初動）、HCI（案内と操作）、ソフトウェア試験（取得と状態）、コミュニティ運営（許諾と報告）を別の検査として扱う。
