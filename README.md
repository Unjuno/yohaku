# YOHAKU / 余白

**世界と、最初の瞬間だけ。あとは会話の中で生まれる。**

YOHAKUは、外部LLMをGMとして遊ぶAIソロTRPGのSeedライブラリです。

- Play: https://yohaku-trpg.unjuno.chatgpt.site/
- Seed review: https://yohaku-trpg.unjuno.chatgpt.site/review
- Story catalog: https://yohaku-trpg.unjuno.chatgpt.site/api/stories

公開中の作品数と一覧はStory catalogを参照してください。

## 遊び始めるには

公開サイトの「開始メッセージをコピー」を押し、ChatGPTなど対応AIのチャットへ貼り付けて送信します。サイト内でAIが動くわけではありません。利用するAIによってログインや利用制限があります。

「今日は変なのがいい」「笑いたい」「怖くないSF」のように気分を伝えられます。プレイ中は「周りを見る」「今の状況は？」「何ができる？」「中断」とそのまま話せます。作品数・ソースの更新と、公開サイトへの反映は別です。

実装・検査・公開反映・人間の試遊の状況は [公開βロードマップ](docs/public-beta-roadmap.md) に分けて記録しています。

## Seedとは

YOHAKUの作品は、完成したシナリオではありません。

各作品で事前に決めるのは、基本的に次の2つです。

### `world`

その世界の基本法則、文化、作品固有の前提。

### `initial_state`

プレイヤーが今どこにいて、何が起きていて、何を見たり聞いたり触れたりできるか。

その先の人物、場所、記録、反応、出来事、結末は、プレイ中の会話で具体化されます。

一度プレイ中に具体化された事実は、そのセッションの事実として扱います。これはGM側の運用ルールであり、プレイヤーにメタ説明するためのものではありません。

## YOHAKUのSeedに入れないもの

Seedには、原則として次のような完成済みシナリオ情報を置きません。

- 固定された筋書きやエンディング
- 犯人や完全な真相
- 攻略手順や唯一の正解
- 敵や怪異の秘密の能力表
- 将来必ず起きるイベント
- GM向けの進行指示を`world`や`initial_state`へ混ぜること

重要なのは「先を決めること」ではなく、**この世界と最初の瞬間だけで遊びたくなること**です。

## Seedを投稿する

新しい世界の入口を歓迎します。コードを書く必要はありません。

GitHubのIssue FormからSeed案を投稿してください。仮題・世界観・初期状態が中心です。紹介文とタグは任意です。

**[Seedを投稿する](https://github.com/Unjuno/yohaku/issues/new?template=seed.yml)**

投稿時に主に見るのは次の点です。

1. その世界ならではの前提があるか
2. 開始直後に自然な行動が生まれるか
3. 人・物・場所・音・記録・装置など、複数の行動の足場があるか
4. 未来や正解を書きすぎていないか
5. 既存Seedと体験が重なりすぎていないか
6. プレイヤーに未知の世界設定を作らせる構造になっていないか

投稿された文章をそのまま採用するとは限りません。方向性が合う場合、YOHAKUの形式に合わせて文面を整理し、必要に応じて投稿者と確認したうえでSeed案を調整します。

## プレイ中の問題を報告する

1回のプレイで気になったことも歓迎します。開始前で作品名が分からない場合や、音声でログが残っていない場合も報告できます。

**[遊んだ感想・問題を送る](https://github.com/Unjuno/yohaku/issues/new?template=play-report.yml)**

GitHubへのログインが必要です。投稿内容は公開されます。

例えば、次のようなものです。

- GM内部のルールやAPI/MCPの話をプレイヤーへ読み上げた
- 「そこに何と書いてある？」と聞いたのに、プレイヤー側へ内容を作らせた
- その世界の住人なら当然知ることを知識クイズにした
- 以前に提示した事実を後から変更した
- 予定された筋書きへ強引に戻した
- 紹介されたジャンルと違う方向へ勝手に変えた

Issue Formには、可能なら問題が起きた前後の短い抜粋と「どう返ってほしかったか」を書いてください。個人情報や共有したくない会話内容は削除してください。

## 採用までの流れ

Seed投稿はおおむね次のように扱います。

1. Issue Formで提案
2. 世界観・初期状態・既存Seedとの重複をレビュー
3. 必要ならIssue上で確認
4. YOHAKU形式に合わせて下書きを整理
5. 短い回帰プレイで、未知情報の丸投げ・事実改変・固定プロット化などを確認
6. 問題なければCatalogへ追加

「投稿数を増やすこと」自体は目的ではありません。既存作品と違う体験があり、Seedとして成立しているものを優先します。

## リポジトリ構成

- `lib/stories.ts` — 既存Seedと検索・取得処理
- `lib/additional-seeds.ts` — 追加Seedの集合
- `lib/experience-gap-seeds.ts` — 既存Catalogで薄かった体験領域を補うSeed
- `lib/field-seeds.ts` — 報道・ケア・保育・インフラ・科学・儀礼・農業・物流のSeed
- `lib/config.ts` — 共通GMガイド
- `app/mcp/` — Remote MCP
- `app/api/stories/` — HTTP Story API
- `app/review/` — Seed review
- `tests/` / `scripts/` — 契約・回帰チェック

開発環境やSites固有の実装メモは [docs/development.md](docs/development.md) に移しています。
